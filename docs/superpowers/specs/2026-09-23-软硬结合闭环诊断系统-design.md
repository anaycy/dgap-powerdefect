# 软硬结合·边端自治·闭环诊断 电力缺陷边缘智能系统 — 设计文档

> 日期：2026-09-23 · 状态：待评审
> 竞赛：第三届"明理杯" / 挑战杯 · 科技发明制作 B 类 · 信息技术（计算机）
> 对标项目：云协智端（全国铜奖，电信学院）

---

## 1. 背景与问题

当前项目「面向电力边缘设备的缺陷感知自适应轻量化检测系统」（DGAP）已有：2 类 3095 张数据集、缺陷感知剪枝/蒸馏/量化算法、树莓派部署脚本。但存在三个评委视角的短板：

1. **形态是"检测 demo"，不是"系统"**：检测出缺陷就结束，没有分级/定位/预警/工单，缺少闭环。
2. **软硬脱节**：只有树莓派跑模型，没有"采集→感知"的硬件侧，对标云协智端的"板卡+网关"缺失。
3. **定位可被替代**：纯"轻量化检测"容易被无人机/机器狗巡检整机方案覆盖，因为它是"别人项目的一环"而非主角。

**四个真实痛点（对应创新点，写进申报书）**：
- P1 边缘算力受限，高精度模型跑不动；
- P2 通用剪枝/量化对小目标缺陷"一视同仁"，压缩后精度暴跌；
- P3 可见光+红外融合需要同一场景配对数据，但**配对数据集不存在**（纯红外数据集多、配对图没有）；
- P4 现有方案多是"检测器"，缺"检测→诊断→决策→执行"闭环。

---

## 2. 项目重新定位

从"轻量化检测系统"升级为 **软硬结合、边端自治、闭环诊断的电力缺陷边缘智能系统**。

对标云协智端「硬件板卡+网关 → 边缘算力 → 平台」三层，扩展为**四层**：

| 层 | 云协智端 | 本项目 | 状态 |
|---|---|---|---|
| 硬件层 | 智能采集板卡 + 泛兼容网关 | 自研多源采集板卡 + 树莓派边缘网关 | 软件实做 / 硬件写成员2指南 |
| 边缘算力层 | 算力下沉 + 嵌入型检测 | 缺陷感知自适应轻量化（已有算法内核） | 已有，保留 |
| 平台/应用层 | 行业AI模型 + 监测平台 | 闭环诊断终端 + 一键部署平台 | 本次实做 |
| 跨模态层 | — | 无配对可见光+红外决策级融合 | 本次实做 |

**一句话新定位**：不是"检测器"，是"采集 → 检测 → 诊断 → 预警 → 工单"的完整闭环。

## 3. 子系统设计

### 3.1 闭环诊断引擎（纯软件，`dgap/diagnosis.py`）

输入：ultralytics 检测结果（boxes + 原始图 + 可选元信息）。输出：诊断报告 + 告警 JSON + 标注图。

- **分级**：类别基础风险 × 面积 × 置信度 → 紧急 / 严重 / 一般 / 注意 四档。销钉缺失默认高权重；绝缘子破损按面积分档。
- **定位**：从文件名/元信息提取 杆塔号·线路·GPS；无元信息则输出图像内相对位置（归一化坐标）。
- **预警**：结构化 JSON（时间戳、类别、等级、位置、置信度）+ 可读文本。
- **工单**：按等级生成运维建议（如"销钉缺失=紧急，建议 3 日内补装"）。
- 无新依赖，纯 Python。接入三处：检测 demo、网关、部署平台。

### 3.2 可视化一键部署平台（Web，`scripts/40_platform.py`）

Gradio（与现有 30_demo_ui 一致），网页点按钮走完：上传数据集 → 训练 baseline → 敏感性分析 → 剪枝 → 蒸馏 → 量化导出 → 自动生成评估报告（含消融对比表）。长任务用 `gr.Progress` 带进度条，同步执行即可满足答辩演示。

### 3.3 边缘网关 + 自研采集板卡（软硬结合）

- **软件（本次实做）**：
  - 树莓派网关 app（`scripts/41_gateway.py`）：读摄像头 + 传感器 → ONNX 推理 → 闭环诊断 → 本地报告 + MQTT 上报平台。
  - 采集板卡模拟器（`scripts/42_board_simulator.py`）：无真 PCB 也能跑通全流程，按协议发 JSON 传感器数据。
  - 板卡↔网关通信协议：JSON over UART（USB 串口）/ MQTT（WiFi），定义在成员2指南。
- **硬件（写成员2指南）**：采集板卡架构框图、器件选型/BOM、传感器接口（可见光摄像头、红外测温 MLX90640、温湿度 DHT22、振动 SW-420/MPU6050）、MCU 选型（ESP32，WiFi 便宜易上手）、PCB 设计要点、打样流程。

### 3.4 无配对跨模态决策级融合（`dgap/fusion.py`）

针对 P3（配对数据不存在）：不做特征级融合（需配对），改**决策级融合**——可见光模型与红外模型各自推理，结果在决策层按类别置信度加权合并 + 跨模态 NMS，互补漏检。红外数据获取、IR 模型训练写进 README「展望」，并在 `分工与计划.md` 列为成员1后续任务。

## 7. 技术选型与约束

- 部署平台：Gradio（复用现有栈，避免引入 Streamlit 增加学习成本）。
- 网关：Python + onnxruntime（复用）+ `paho-mqtt`（MQTT，新增依赖）+ `pyserial`（UART 到板卡，新增依赖）。
- 板卡 MCU：ESP32（WiFi 内置、便宜、Arduino/ESP-IDF 生态成熟，适合学生）。
- 融合：纯 Python，无新依赖。
- 闭环诊断：纯 Python，无新依赖。
- 所有新增依赖在 `requirements.txt` 中标注"可选"，避免破坏现有环境。

## 8. 风险与依赖

- 红外数据集：若无可用公开集，融合模块降级为"框架 + 仿真数据"演示，IR 训练写指南。
- 板卡打样：受限于经费/周期，PCB 打样可能做不了 → 用 ESP32 + 面包板/现成模块搭原型，硬件设计写指南。
- 部署平台训练时长：答辩演示时用已训好的缓存模型路径，平台流程用"小数据集快跑"演示。
