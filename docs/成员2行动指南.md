> 目标：把成员1 训练/剪枝/量化后的模型部署到**树莓派5（8GB）+ 摄像头 + 自研采集板卡**，

## 0. 已有硬件

| 硬件 | 说明 |
|---|---|
| 树莓派 5（8GB） | 已购，主动散热（风扇/散热片），不然满载降频 |

## 2. 自研采集板卡设计（对标云协智端硬件层）

### 2.1 架构框图（文字）

```
[MLX90640 红外] ──I2C──┐
[DHT22 温湿度]  ──GPIO─┤
[SW-420 振动]   ──GPIO─┼──> [ESP32 MCU] ──UART(USB串口) 或 WiFi/MQTT──> [树莓派网关]
[可见光摄像头]   (直接接树莓派 USB) ──────────────────────────────────────────┘
```

- **板卡**只负责"多源传感器采集 + 打包上报"，不跑 AI（AI 在树莓派网关本地跑，算力下沉）。
- **树莓派网关**负责：读摄像头 + 收板卡数据 → ONNX 推理 → 闭环诊断 → 告警/工单 → MQTT 上报平台。

### 2.2 器件与接口

| 器件 | 接口 | ESP32 引脚示例 |
|---|---|---|
| MLX90640 | I2C（SDA/SCL） | GPIO21(SDA)/GPIO22(SCL) |
| DHT22 | 单总线 GPIO | GPIO4 |
| SW-420 | 数字/模拟 GPIO | GPIO34(ADC) |
| 供电 | 5V | 树莓派 5V USB 或独立 5V 电源 |

### 2.3 通信协议（板卡 → 网关，JSON）

协议名 **`dgap-board/v1`**，板卡周期（如每 2 秒）发一条 JSON：

```json
{
  "ver": "dgap-board/v1",
  "ts": 1758000000.0,
  "seq": 0,
  "line": "10kV 明珠线",
  "tower": "T102",
  "gps": {"lat": 31.23, "lng": 121.47},
  "thermal": {"grid_avg": 35.0, "max": 45.0},
  "humidity": 60.0,
  "vibration": 0.1
}
```

> 字段与 `scripts/42_board_simulator.py` 的 `sample()` 完全一致（可先跑模拟器联调）。
> 传输方式二选一：**UART（USB 串口，最简单）** 或 **WiFi/MQTT（可无线远传）**。

### 2.4 固件

用 **Arduino IDE**（最简单）或 ESP-IDF 写，逻辑：

```
初始化传感器 → 循环：读各传感器 → 组 JSON → UART.println(json) 或 MQTT publish → 延时 2s
```

Arduino 关键库：`Adafruit_MLX90640`、`DHT`、`ArduinoJson`、`PubSubClient`（若走 MQTT）。

### 2.5 若打样 PCB（可选加分项）

1. 用 **嘉立创 EDA** 画原理图（ESP32 最小系统 + 传感器接口 + 5V 稳压）。
2. 布局/布线 → 导出 Gerber → 嘉立创打样（约 30 元/5 片）。
3. 打样做不了就**面包板原型 + 拍照**，申报书写"实验室阶段原型"即可，别过度承诺。

## 3. 树莓派部署流程

### 3.1 烧录系统

1. 电脑下载 [Raspberry Pi Imager](https://www.raspberrypi.com/software/)。
2. 插 SD 卡 → 选 **Raspberry Pi OS (64-bit)**（Bookworm）。
3. 点右下角齿轮，预设：主机名 `rpi-power`、用户名 `pi`、**开启 SSH**、配置 WiFi（和电脑同网段）。
4. 烧录 → 插进树莓派 → 上电。

### 3.2 首次开机 + 装依赖

```bash
ssh pi@rpi-power.local
sudo apt update && sudo apt full-upgrade -y && sudo reboot

# 装 pip 与依赖
sudo apt install -y python3-pip python3-opencv
pip3 install --upgrade pip
pip3 install numpy onnxruntime pillow
```

**验证 onnxruntime 是 ARM64 版**：

```python
python3 -c "import onnxruntime as ort; print(ort.__version__); print(ort.get_available_providers())"
# 应看到 ['CPUExecutionProvider', ...]
```

### 3.3 把模型拷到树莓派

成员1 在 PC 上跑 `13_quantize_export.py` 生成 `runs/export/*.onnx`。**用 fp32 那个**（fp16 在 CPU 上没加速）。

```bash
mkdir -p ~/dgap && cd ~/dgap
# 从 PC 用 scp 传（在 PC 上执行，换成实际 IP）
scp runs/export/*.onnx pi@rpi-power.local:~/dgap/
# 把纯逻辑模块也拷过去（不依赖 torch，可直接 import）
scp dgap/diagnosis.py pi@rpi-power.local:~/dgap/
```

## 4. 网关 app 运行

`scripts/41_gateway.py` 是网关主程序，PC 上和树莓派上都能跑。

### 4.1 PC 上先联调（无硬件）

```bash
.venv/Scripts/python.exe scripts/41_gateway.py --dry-run
```

应打印一条含 `level / 建议 / 杆塔号` 的告警 JSON + `[网关] dry-run 走通`。

### 4.2 树莓派上跑（完整流程）

把 `scripts/41_gateway.py` 也 `scp` 到树莓派，按 41_gateway.py 里的 `infer()` 逻辑接摄像头 + 板卡数据，形成完整循环：

```
读摄像头帧 → letterbox → ONNX 推理 → 检测结果 + 板卡 JSON(杆塔号/GPS/温度)
   → dgap.diagnosis.diagnose() 分级/定位/预警/工单 → 本地打印报告 + MQTT 上报平台
```

> 完整采集→检测→诊断→上报的接线与循环逻辑以 `41_gateway.py` 注释为准；板卡先跑 `42_board_simulator.py --stdout` 联调。

### 4.3 单张图/摄像头推理脚本（备用，最简版）

若网关脚本还没调通，可先用最简 ONNX 推理脚本验证模型（letterbox 前处理 → ONNX → NMS 后处理 → 画框）。逻辑同原 `树莓派部署步骤.md` §4 的 `detect.py`。

## 5. 性能测试（写进报告的关键数据）

```bash
# 树莓派上测单张推理耗时（CPU）
python3 - <<'PY'
import time, numpy as np, onnxruntime as ort
s = ort.InferenceSession("best_fp32.onnx", providers=["CPUExecutionProvider"])
x = np.random.rand(1, 3, 640, 640).astype(np.float32)
name = s.get_inputs()[0].name
for _ in range(5): s.run(None, {name: x})
t = time.time()
for _ in range(50): s.run(None, {name: x})
print("平均推理 %.1f ms / %.1f FPS" % ((time.time()-t)/50*1000, 50/(time.time()-t)))
PY
```

**测功耗**：用 USB 功率计读整机功耗，记录"空闲 vs 满载推理"；或 `vcgencmd measure_volts` 看电压。

**端到端时延**：从摄像头抓帧到输出告警 JSON 的耗时（在网关脚本里打时间戳）。

**对照**：把**基线模型**和**压缩后模型**各跑一次，记录参数量/FPS/时延/功耗，做出"压缩后 FPS 提升 ≥2.2 倍"的实物数据（对应申报书技术指标）。

## 7. 常见坑

| 现象 | 处理 |
|---|---|
| `onnxruntime` 装不上 | 确认 64 位系统；`pip3 install --no-cache-dir onnxruntime` |
| 输出形状对不上（不是 8400） | 模型 imgsz 不同，`IMGSZ` 改成导出时的值 |
| 检测框全错位 | letterbox 的 `(dw,dh)/r` 和后处理 un-letterbox 要对上 |
| 摄像头打不开 | USB 摄像头换端口；CSI 用 `libcamera-hello` 先验证 |
| CPU 满载发热降频 | 加风扇，或把 imgsz 降到 480/416 |
| 板卡串口读不到数据 | 查波特率/引脚；先用 `42_board_simulator.py --stdout` 确认协议字段 |
