## 一、演示界面（闭环诊断 demo）

### 1.1 目标

一个网页：上传图片 → 选模型（基线 vs 压缩模型）→ 检测 → **分级（紧急/严重/一般/注意）+ 定位 + 运维建议工单**。用于答辩现场演示 + 录屏。

> 界面已落地为 `scripts/30_demo_ui.py`，**不要**再用下面的旧"只画框"代码。运行：

```bash
.venv/Scripts/pip.exe install gradio
.venv/Scripts/python.exe scripts/30_demo_ui.py
# 浏览器打开 http://127.0.0.1:7860
```

### 1.2 演示要点

上传一张缺陷图（破损绝缘子 / 销钉缺失）→ 点"检测并诊断" → 左侧显示**分级彩色框**（紧急=红、严重=橙、一般=黄、注意=蓝），右侧显示诊断报告：

```
[紧急] missing_pin conf=0.91 @ 10kV 明珠线T102
   建议: 立即安排检修，建议 24 小时内处理
```

### 1.3 演示视频（3~5 分钟）

脚本录屏：开机 → 打开界面 → 上传缺陷图 → 检出分级 + 工单 → 切模型对比 FPS/参数量。**重点拍"压缩后检测结果几乎不变、FPS 翻倍 + 自动出工单"**。

## 二、申报书填写模板（B3 表）

### B3-1 作品设计、发明的目的和基本思路，创新点，技术关键和主要技术指标

**目的**：电力线路巡检缺陷（破损绝缘子、销钉缺失）依赖人工/云端，算力受限的边缘设备跑不动高精度检测模型；且现有方案多是"检测器"，缺闭环。本项目把缺陷检测模型轻量化下沉到边缘设备，并形成「采集 → 检测 → 分级 → 预警 → 工单」闭环诊断。

**基本思路**：电力缺陷数据集 → 训练高精度 YOLO 模型（教师）→ 缺陷感知敏感性分析 → 自适应混合粒度剪枝量化 → 缺陷区域知识蒸馏 → ONNX 导出 → 边缘网关（采集+检测+闭环诊断）→ 告警/工单。

**创新点**（五条）：
1. 缺陷感知自适应轻量化：分层特征贡献度评估 + 混合粒度剪枝量化联合优化 + 缺陷区域蒸馏，保护小目标缺陷通道。
2. 闭环诊断引擎：检测结果 → 分级（紧急/严重/一般/注意）→ 定位 → 预警 → 工单。
3. 无配对跨模态决策级融合：可见光与红外各自检测、决策级合并，不依赖不存在的配对数据。
4. 软硬结合：自研多源采集板卡 + 树莓派边缘网关，边端自治。
5. 可视化一键部署平台：训练 → 压缩 → 导出 → 评估，网页点按钮完成。

**技术关键**：C2f 重参数化剪枝、缺陷感知重要性打分、通道对齐蒸馏、混合精度导出、闭环诊断分级、决策级融合。

**主要技术指标**：参数量压缩 ≥60%、推理速度提升 ≥2.2 倍、mAP@0.5 下降 ≤3%、边缘端到端时延/整机功耗（成员2 实测）。

> 模板：逐条"现有技术缺陷 → 本作品改进 → 量化进步 + 参考文献"

| 现有技术 | 缺陷 | 本作品改进 | 显著进步 | 参考文献 |
|---|---|---|---|---|
| 全局统一剪枝/量化 | 对小目标"一视同仁"，压缩后小缺陷精度暴跌 | 基于 BN 缩放因子+激活响应评估各层对缺陷的贡献度，缺陷敏感层低剪枝/高位宽，冗余层高剪枝/低位宽 | 同压缩比下小目标 mAP 高 5~8% | Network Slimming (Liu ICCV'17)；torch_pruning |
| 通用知识蒸馏 | 只模仿整体输出，小目标/少数类被淹没 | 缺陷区域加权 + 小目标锚定权重 + 困难样本动态加权 | 压缩后小目标漏检率下降 | Hinton KD；任务对齐蒸馏 |

| 单一"检测器" | 检测完即结束，无决策/执行 | 分级 + 定位 + 预警 + 工单闭环 | 从"检测器"到"诊断系统" | 电力运检闭环/工单系统 |

## 三、C 表：当前国内外同类课题研究水平概述（文献综述模板）

分三段，每段 200~300 字：

1. **模型压缩方向**：结构化剪枝（BN 缩放因子/重要性）、量化感知训练、知识蒸馏的代表工作，指出"普遍全局统一、缺少对特定场景小目标的针对性"。
2. **电力缺陷检测方向**：YOLOv5/v8 在绝缘子/销钉/金具缺陷检测的应用，指出"多数只关注精度、忽略边缘部署与小目标"。
3. **边缘部署方向**：ONNX/TensorRT/NCNN 等，指出"算法研究与工程部署脱节"。

结尾总结：**现有方案的三点局限 → 本作品的针对性改进**（可补充：跨模态配对数据缺失、缺闭环两点局限）。
